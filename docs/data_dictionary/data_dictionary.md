# Data Dictionary — Commercial Alfa LTDA

This document describes the metadata structure, data types, keys, and integrity constraints of the Commercial Alfa LTDA data ecosystem, modeled in a PostgreSQL environment using the Star Schema (Dimensional Model) standard.

---

## 1. Fact Table: `fato_vendas`
* **Description:** Stores the quantifiable cosmetic sales events (metrics) and the foreign keys that connect the event to its context (dimensions).

| Field | Type | Key | Constraint | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id_venda` | SERIAL | PK | NOT NULL, UNIQUE | Unique and incremental identifier for each sales transaction. |
| `data_venda` | DATE | FK | NOT NULL | Date of sale. Relationship key with the `dim_tempo` table. |
| `id_cliente` | INT | FK | NOT NULL | Foreign key linking to the `dim_clientes` table. |
| `id_produto` | INT | FK | NOT NULL | Foreign key linking to the `dim_produtos` table. |
| `quantidade` | INT | — | NOT NULL, CHECK (> 0) | Volume of boxes shipped in the transaction. Does not accept negative or null values. |
| `valor_total` | NUMERIC(12,2) | — | NOT NULL, CHECK (>= 0) | Gross revenue generated by the transaction in dollars ($). |

---

## 2. Dimension Table: `dim_clientes`
* **Description:** Contains the attributes and geographic context of the clients/vendedores responsible for the transactions.

| Field | Type | Key | Constraint | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id_cliente` | SERIAL | PK | NOT NULL, UNIQUE | Unique and incremental identifier for the client/vendedor. |
| `nome_cliente` | VARCHAR(255) | — | NOT NULL | Full name of the seller or corporate client. |
| `pais_cliente` | VARCHAR(100) | — | NOT NULL | Country of origin or commercial operation of the client. |

---

## 3. Dimension Table: `dim_produtos`
* **Description:** Stores the product catalog and their respective market categorizations.

| Field | Type | Key | Constraint | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id_produto` | SERIAL | PK | NOT NULL, UNIQUE | Unique and incremental identifier for the product. |
| `nome_produto` | VARCHAR(255) | — | NOT NULL | Commercial name of the cosmetic product. |
| `categoria_produto` | VARCHAR(100) | — | NOT NULL | Market category of the product (e.g., 'Cosméticos'). |

---

## 4. Dimension Table: `dim_tempo`
* **Description:** Dimensional time table to enable time-series, seasonality, and market trend analyses.

| Field | Type | Key | Constraint | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id_tempo` | DATE | PK | NOT NULL, UNIQUE | Calendar date acting as the structural primary key (Format: YYYY-MM-DD). |
| `ano` | INT | — | NOT NULL | Calendar year corresponding to the date. |
| `mes` | INT | — | NOT NULL | Month number corresponding to the date (1 to 12). |
| `dia` | INT | — | NOT NULL | Day of the month corresponding to the date (1 to 31). |
| `dia_da_semana` | VARCHAR(50) | — | NOT NULL | Day of the week name translated into Portuguese (e.g., 'Segunda', 'Terça'). |

---

## 5. Implemented Performance Indices
To mitigate processing bottlenecks (Table Scans) during relational joins, the following structures were indexed:
* `idx_fato_data` (B-Tree on column `fato_vendas.data_venda`)
* `idx_fato_cliente` (B-Tree on column `fato_vendas.id_cliente`)
* `idx_fato_produto` (B-Tree on column `fato_vendas.id_produto`)
* `idx_clientes_pais` (B-Tree on column `dim_clientes.pais_cliente`)
